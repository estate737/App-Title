# PS5 13.60 support

App Title supports the verified Hermes v89 HomeUI from PS5 13.600.007
(`rnps-home 13.0.0+22834`). The existing 11.60 profile remains supported.
Unknown or altered profiles are rejected before writing to the bundle.
Only numeric metadata and digests are included; no firmware bundle is shipped.

The 13.60 profile supports the existing top/bottom, inside/outside and color
settings. Inside placement preserves the native title background; outside
placement reserves space for the ID and native game title.

## Run and configure

Build `dist/App_Title_v0.2.8.elf` using the instructions in `BUILDING.md`, then
load it with a compatible privileged ELF loader after jailbreak.
Reboot before replacing a resident payload or retrying after ShellUI restarts.

New Media shortcut registration on firmware 12+ remains unavailable. Configure
`/data/AppTitle/config.ini` over FTP before launch:

```ini
enabled=1
position=bottom
color=ffffff
placement=outside
```

`position` also accepts `top`; `placement` also accepts `inside`. The existing
settings server remains bound to localhost.

## Override compatibility

The exact linked HomeUI used by Override 0.5.5/0.5.6 is recognized. Other linked
revisions are rejected. Override's panel and top-navigation functions are
preserved.

When Override loads first, App Title preserves its existing ioctl detour and
styles the linked bundle afterwards. When App Title loads first, Override must
implement the ABI in `include/app_title_override_bridge.hpp`. The companion
Override 0.5.6 implementation is required for this order and is maintained
separately; older Override loaders must not be loaded over App Title's hook.

The bridge accepts one process-local transform and runs it before styling.
Override delegates the HomeUI refresh to App Title's existing Update callback.
Disabling title IDs preserves the Override panel. The native bootstrap worker
detaches from Mono after metadata/JIT preparation.

## Console verification

On PS5 13.600.007, loading App Title before the companion Override 0.5.6 applied
both modifications with zero HomeUI reload errors. Both IDs and the button
remained visible after opening the native Override app and returning home.
The opposite order has been verified with host callbacks, but has not been
console-tested with the matching new pair.
